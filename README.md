# 2008Pars — فروشگاه قطعات پژو ۲۰۰۸

فروشگاه اینترنتی قطعات یدکی پژو ۲۰۰۸، فارسی و راست‌به‌چپ.

> **وضعیت: فاز ۱ — کاتالوگ عمومی.**
> اسکیمای کاتالوگ، لایهٔ مخزن و مرور عمومی محصول‌ها ساخته شده است.
> هنوز سبد خرید، تسویه، سفارش، پرداخت، پنل مدیریت و احراز هویت نیست.
> کاتالوگ عمدا خالی است: هیچ دادهٔ نمونه‌ای در مهاجرت‌ها وجود ندارد.

## پشته فنی

| لایه | انتخاب |
|---|---|
| اجرا | Node.js ۲۰/۲۲ LTS |
| وب | Express 5 |
| قالب | Nunjucks (رندر سمت سرور) |
| پایگاه داده | PostgreSQL (تنها گزینه — SQLite پشتیبانی نمی‌شود) |
| تصویر | sharp |
| رمز عبور | Argon2id (فاز احراز هویت) |
| اسکریپت سمت کاربر | جاوااسکریپت ساده، بدون فریم‌ورک |

## راه‌اندازی

```bash
npm install
cp .env.example .env      # سپس مقدارها را پر کنید
npm run migrate           # نیازمند یک PostgreSQL در دسترس
npm run dev
```

## مسیرهای عمومی

| مسیر | کار |
|---|---|
| `/` | صفحهٔ اصلی |
| `/products` | همهٔ محصول‌ها، صفحه‌بندی‌شده |
| `/category/:slug` | محصول‌های یک دسته |
| `/brand/:slug` | محصول‌های یک برند |
| `/product/:slug` | جزئیات محصول |
| `/search?q=` | جست‌وجو در نام، کد کالا و شماره فنی |
| `/health` | سرویس بالاست؟ |
| `/health/db` | پایگاه داده در دسترس است؟ |

نشانی‌ها فارسی‌اند: `/category/لوازم-ترمز`. نرمال‌سازی یکسان روی هر دو سمت
اعمال می‌شود — هنگام ساختن نشانی و هنگام جست‌وجوی آن — پس `كليد` با کاف و
یای عربی هم به همان صفحه می‌رسد.

پارامترهای پذیرفته‌شده: `page`، `sort` (`newest` / `price-asc` /
`price-desc` / `name`)، `brand`، `availability`. هر پارامتر دیگری **نادیده
گرفته می‌شود** — فهرست سفید، نه فهرست سیاه.

## ساختار

```
src/
  app.js            ساخت برنامه Express
  server.js         راه‌اندازی و خاموشی تمیز
  config/           تنظیمات، همه از متغیر محیطی
  db/               اتصال PostgreSQL، مهاجرت‌گر
    repositories/   دسترسی به داده (کارخانه + تزریق)
  middleware/       امنیت، CSRF، محدودیت نرخ، اعتبارسنجی آپلود
  routes/           مسیرهای HTTP
  controllers/      منطق صفحه
  services/         قالب‌بندی فارسی، نشانی، پردازش تصویر، صفحه‌بندی
  views/            قالب‌های Nunjucks
public/             دارایی‌های عمومی (CSS، JS، تصویر ایستا)
storage/            ← بیرون از webroot، هرگز در Git
  originals/        تصویر اصل، خصوصی
  products/         مشتق‌های واترمارک‌خورده، عمومی از راه /media/products
  receipts/         رسید پرداخت، خصوصی، فقط با احراز هویت
migrations/         فایل‌های SQL شماره‌دار
scripts/            ابزارهای کمکی
tests/              آزمون‌ها (node:test)
```

## لایهٔ دسترسی به داده

مخزن‌ها کارخانه‌اند و اجراکنندهٔ کوئری را از بیرون می‌گیرند:

```js
const products = createProductRepository(db);   // db: هر چیزی با ‎.query()‎
```

`src/db/repositories/index.js` آن‌ها را به استخر اتصال تولید سیم می‌کند، و
`createApp({ repositories })` اجازه می‌دهد مجموعهٔ دیگری تزریق شود.
آزمون‌ها از همین راه PGlite می‌دهند — PostgreSQL واقعی (نسخه ۱۸)
کامپایل‌شده به WebAssembly، و فقط وابستگی توسعه. به همین دلیل لایهٔ اتصال
تولید (`src/db/index.js`) هیچ‌وقت برای آزمون عوض نمی‌شود.

یک محدودیت آگاهانه: PGlite متد `connect()` ندارد، پس `runMigrations()` که
روی قفل مشورتی بنا شده روی آن اجرا نمی‌شود. آزمون‌ها خودِ فایل‌های SQL را
اجرا می‌کنند؛ یعنی SQL کاملا آزموده می‌شود، ولی قفل‌گذاری و دفترداری
`schema_migrations` فقط روی PostgreSQL واقعی.

## جست‌وجو

دو مسیر جدا، چون دو نیت متفاوت‌اند:

* **شمارهٔ فنی یا کد کالا** — تطبیق دقیق یا پیشوندی روی شکل نرمال‌شده.
  `9678-191-580`، `9678 191 580` و `۹۶۷۸۱۹۱۵۸۰` همگی یک چیزند، چون مشتری
  شماره را از روی قطعهٔ کهنه می‌خواند و جداکننده‌ها را حدس می‌زند.
* **نام** — تطبیق سه‌نویسه‌ای با `pg_trgm`، چون املا و کامل بودن نام متغیر است.

اگر ارائه‌دهندهٔ PostgreSQL اجازهٔ `CREATE EXTENSION pg_trgm` ندهد، مهاجرت
۰۰۱ با خطای روشن متوقف می‌شود. این عمدی است: بهتر است همان لحظه بدانیم تا
اینکه جست‌وجو بی‌سروصدا ضعیف شود.

## قاعده‌های پروژه

**پول.** مبلغ‌ها به **تومان** و به‌صورت `BIGINT` ذخیره می‌شوند. رشتهٔ
فارسیِ قالب‌بندی‌شده هرگز در پایگاه داده نمی‌رود — چون نه جمع‌پذیر است، نه
مرتب‌شدنی. تبدیل فقط در لحظه نمایش، با فیلتر `toman`.

**ارقام.** ورودی کاربر پیش از اعتبارسنجی با `toEnglishDigits()` نرمال
می‌شود؛ خروجی با `faDigits()` فارسی می‌شود.

**شماره فنی در متن فارسی.** همیشه داخل `<bdi>` — وگرنه جهتش در چیدمان
راست‌به‌چپ به‌هم می‌ریزد.

**زمان.** `TIMESTAMPTZ` و UTC در پایگاه داده؛ نمایش شمسی با `formatJalali()`.

**فایل‌های آپلودی.** هرگز بایت خام کاربر ذخیره نمی‌شود. هر تصویر با sharp
دوباره رمزگذاری می‌شود، نامش UUID تصادفی است، نوعش از روی بایت‌های ابتدایی
تشخیص داده می‌شود (نه پسوند)، و `storage/` بیرون از webroot است.

**SQL.** فقط کوئری پارامتری (`$1`, `$2`). چسباندن مقدار داخل رشتهٔ SQL ممنوع.

**رازها.** هیچ رمز، کلید یا رشتهٔ اتصالی داخل کد یا Git نیست. فقط `.env`،
که در `.gitignore` است.

**خطا.** جزئیات خطای داخلی هرگز به کاربر نمی‌رسد — فقط یک کد ارجاع که در
لاگ سرور قابل پیگیری است.
